# V4 — Decodificação de pacotes APRS

## Objetivo

A V4 evolui o APRS ESP32 Web Monitor para interpretar informações básicas das linhas recebidas do APRS-IS.

Além de armazenar o pacote original, o firmware identifica o indicativo, o caminho de roteamento, o tipo de pacote e, quando compatível, a posição geográfica e o símbolo APRS.

## Funcionalidades

- Recepção de dados APRS-IS herdada da V3.
- Identificação do indicativo e do caminho de roteamento.
- Classificação inicial do tipo de pacote.
- Decodificação de posições APRS não comprimidas.
- Conversão de latitude e longitude para graus decimais.
- Identificação da tabela e do código do símbolo.
- Histórico circular dos últimos 10 pacotes.
- API JSON com dados estruturados.
- Painel web com indicativo, tipo, posição e pacote original.
- OLED com resumo do último pacote recebido.

## Hardware

- ESP32.
- OLED SSD1306 I2C de 128 × 64 pixels.

A ligação permanece igual às versões anteriores:

| OLED | ESP32 |
|---|---|
| VCC | Conforme especificação do módulo |
| GND | GND |
| SDA | GPIO 21 |
| SCL | GPIO 22 |

## Bibliotecas

- Adafruit SSD1306
- Adafruit GFX Library

As bibliotecas de Wi-Fi, TCP, servidor HTTP e I2C são fornecidas pelo pacote de placas ESP32.

## Configuração

A V4 mantém a configuração de Wi-Fi e APRS-IS da V3. Configure as credenciais da rede doméstica no firmware antes de compilar.

O servidor APRS-IS, a porta, o indicativo de identificação e o filtro devem ser configurados conforme o ambiente utilizado. A implementação destina-se à recepção, não à transmissão.

## API

### `GET /api/status`

Retorna informações de conectividade, contadores e estado do sistema.

### `GET /api/packets`

Retorna o histórico de pacotes, incluindo:

- `callsign`: indicativo da estação.
- `path`: caminho informado no cabeçalho.
- `type`: classificação inicial do pacote.
- `hasPosition`: indica se uma posição foi decodificada.
- `latitude`: latitude em graus decimais, quando disponível.
- `longitude`: longitude em graus decimais, quando disponível.
- `symbolTable`: tabela do símbolo APRS.
- `symbolCode`: código do símbolo APRS.
- `raw`: linha original recebida.
- `ageSeconds`: tempo aproximado desde a recepção.

Campos de posição e símbolo são omitidos quando o pacote não possui posição decodificada.

## Formatos suportados

A V4 decodifica posições APRS não comprimidas nos formatos com identificadores `!` e `=`, e nos formatos com timestamp ` / ` e `@` conforme a estrutura APRS.

Pacotes com outros tipos de informação continuam sendo armazenados como texto bruto e recebem uma classificação inicial.

Posições comprimidas e formatos complexos ainda não são decodificados nesta versão.

## Testes

1. Copie o firmware da V3 para a pasta da V4.
2. Adicione o parser e substitua as funções indicadas na documentação do desenvolvimento.
3. Compile no Arduino IDE.
4. Grave o ESP32 e abra o Monitor Serial a 115200 baud.
5. Acesse o painel web e consulte `/api/status`.
6. Consulte `/api/packets` e verifique se os campos JSON estão corretos.
7. Compare as coordenadas decodificadas com os campos da linha original.
8. Verifique pacotes sem posição, mensagens e linhas de comentário.
9. Reinicie o ESP32 e confirme que o histórico em RAM começa novamente vazio.

## Limitações

- A decodificação de posição é limitada a formatos não comprimidos.
- A classificação dos tipos de pacote é inicial e não substitui um parser completo da especificação APRS.
- O símbolo é identificado pelo código, mas não é desenhado como ícone gráfico.
- Não há mapa integrado.
- O histórico é volátil e limitado a 10 pacotes.
- A conexão APRS-IS continua sendo TCP sem TLS nesta implementação.
- Não há recepção direta por rádio ou transmissão de pacotes.
