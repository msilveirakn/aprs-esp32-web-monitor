
# V2 — APRS ESP32 Web Monitor

## Objetivo

Evoluir a V1 com uma estrutura de dados para pacotes APRS,
histórico circular, dados simulados e novas rotas HTTP.

## Funcionalidades

- Access Point Wi-Fi.
- Servidor HTTP.
- Painel web responsivo.
- API `/api/status`.
- API `/api/packets`.
- Modelo de dados `AprsPacket`.
- Histórico circular de até 10 registros.
- Geração de pacotes simulados a cada 15 segundos.
- Exibição do último indicativo no OLED.
- Atualização automática do painel a cada 3 segundos.

## Hardware

- ESP32 DevKit compatível.
- OLED SSD1306 I2C 128x64.

## Ligações

| OLED | ESP32 |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SDA | GPIO 21 |
| SCL | GPIO 22 |

## Rede

- SSID: `APRS-ESP32-V2`
- Senha de demonstração: `aprs12345`
- IP padrão: `192.168.4.1`

## Endpoints

| Endpoint | Método | Função |
|---|---|---|
| `/` | GET | Painel web |
| `/api/status` | GET | Estado e estatísticas |
| `/api/packets` | GET | Histórico em JSON |

## Modelo de dados

Cada registro contém:

- `callsign`: indicativo da estação.
- `path`: caminho de demonstração.
- `type`: categoria do pacote.
- `message`: conteúdo de demonstração.
- `receivedAt`: instante local de inserção.

O campo `age` da API representa a idade aproximada
do registro em segundos desde sua inserção no ESP32.

## Limitações

Todos os registros são simulados.

A V2 não implementa:
- Conexão APRS-IS.
- Recepção de áudio por rádio.
- Decodificação AX.25.
- Modulação ou transmissão AFSK.
- GPS ou posição real.

Os campos representam uma estrutura interna de
demonstração, não uma interpretação completa do
formato de pacotes APRS.

## Testes

1. Compilar e carregar o firmware.
2. Conectar ao Access Point.
3. Abrir o painel web.
4. Consultar `/api/status`.
5. Consultar `/api/packets`.
6. Verificar a atualização automática dos registros.
7. Confirmar que o histórico mantém no máximo 10 registros.
